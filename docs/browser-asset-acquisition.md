# Browser asset acquisition feasibility

Research date: 2026-10-18.

For the subsequent inventory-wide source checks, see the [2026-10-19 online asset audit](online-asset-audit.md). It separates current upstream presence from direct browser access and reproduction of exported assets.

Implementation update, 2026-10-19: PJSK `mmj_01_01` now has an app-managed direct downloader. A fresh Chrome profile on a static-only host downloaded the sources, resumed after cancellation and reload, reopened offline, played all 62 passages, and restored saved progress after another restart. See [deployment and reproduction instructions](deployment.md#pjsk-direct-download-prototype).

Manual-import proof, 2026-10-19: the BA JP prologue can be rebuilt from user-selected original files in a browser worker and read offline through all seven choices. The experiment uses no asset server and leaves the production UI unchanged. See the [BA browser import proof](ba-browser-import.md). Direct Fetch access to the official BA source remains blocked by CORS.

Scope: a static, installable Onlystory web app with offline reading, no Onlystory backend, and no developer-paid asset hosting. Users should download content through the app. Requiring the app's extraction and conversion steps can discourage casual external downloads; it does not provide secret or exclusive access.

PJSK has one chapter verified end to end in desktop Chrome. Its sampled external mirror resources were readable in ordinary Chrome. The tested official Blue Archive JP patch resources were blocked by CORS. Public projects establish a GFL1 manifest downloader and a GFL2 model mirror, but neither is a verified complete browser provider for Onlystory. Other chapters, browsers and game providers still require validation.

## Live browser access probes

On 2026-10-18, ordinary headless Google Chrome fetched the recorded URLs from a fresh loopback web origin with no cookies, proxies, extensions or disabled browser security. Successful fetches read the first response-body chunk and canceled the stream. Separate Node requests sent `Origin: https://onlystory.example` and `Range: bytes=0-1023` to inspect response headers. These are access samples, not full downloads, media decode tests or all-region availability checks. The production deployment origin still needs its own test.

## PJSK

The current source importer downloads regional metadata from Sekai World's raw GitHub repositories and story JSON from `storage.sekai.best/sekai-<region>-assets`. Its playback installer uses JP voices and media with CN scripts, plus `sekai-live2d-assets` for model settings, MOC3, textures, physics and motions. This is an existing community asset mirror, not a publisher endpoint or Onlystory-owned storage. Sources: [source URL construction](../scripts/pjsk-scenario.mjs), [source importer](../scripts/pjsk-import.mjs), [media installer](../scripts/pjsk-media.mjs), [upstream regional configuration](https://github.com/Sekai-World/sekai-viewer/blob/dev/src/utils/urls.ts).

The sampled source formats already suit browser playback. This avoids raw Unity bundle extraction for those resources. However, the installer currently runs in Node, hashes and writes files on disk, resolves media dependencies and voice filenames, applies reviewed model/voice overrides, rewrites Live2D references and compiles the native scenario into the shared reader's program. Browser work must preserve that logic with browser hashing and persistent storage, rather than point the player at a single remote URL. The scenario and program compilers are useful starting points for separating filesystem work from transformation. Sources: [scenario decoder](../scripts/pjsk-scenario.mjs), [program compiler](../scripts/pjsk-program.mjs), [media installer](../scripts/pjsk-media.mjs), [voice resolver](../scripts/pjsk-voice-listing.mjs), [model corrections](../scripts/pjsk-model-overrides.mjs).

The downloader now covers every imported CN main-story and event chapter in the current catalog. Pinned compressed recipes describe original sources, checksums and model-reference edits. The app downloads the selected chapter's script and media from the mirror, rebuilds its program and text with the shared compiler, and verifies the generated outputs before marking it installed. SHA-256 covers the acquired originals; deferred voices use their pinned upstream size and MD5. The catalog includes choices, movies, reviewed source-identity corrections and the existing performance approximations. Sources: [browser downloader](../src/downloads/pjsk.ts), [catalog builder](../scripts/build-pjsk-download-catalog.mjs), [coverage record](pjsk-download-catalog.json), [static-host browser test](../tests/pwa/pjsk-download.spec.ts).

The additional CN event chapters whose scripts are absent from the mirror remain unavailable. The [current source check](pjsk-unavailable-source-check.json) records their HTTP responses. This implementation covers the imported CN main/event library, rather than every region or card-side story. The production compiler reconstruction check covers every recipe and unique model setting; live browser and Windows tests cover representative chapters and offline restart. See [standalone usage and verification](standalone-app.md).

Treat source changes, throttling and disappearance as recoverable provider failures. Access on this machine does not guarantee availability for every user's network, nor continued service by the independent mirror.

This route does not meet app-exclusive downloading. The mirror already exposes usable JSON, image, audio and model files. App-managed storage and automatic dependency resolution make Onlystory convenient, but do not add access control to the source.

## Blue Archive JP

The current pipeline combines a pinned BA Archive text snapshot with an official JP Android patch catalog. It acquires selected files from `prod-clientpatch.bluearchiveyostar.com`. Prologue text comes from the community snapshot; later imported story data is decoded from a pinned official database. Sources: [pipeline notes](blue-archive-pipeline.md), [acquisition wrapper](../scripts/acquire-ba.mjs), [asset downloader](../scripts/ba-acquire.py), [event text extraction](../scripts/ba-event-source.py), [main-story text extraction](../scripts/ba-main-source.py).

The five tested official resource paths returned valid partial HTTP responses outside the browser, while browser console errors explicitly identified missing `Access-Control-Allow-Origin`. This is a browser access blocker for downloading readable bytes, caching verified content and extracting models. Successful command-line downloads and displaying some media directly in HTML do not establish a working browser importer. CORS must be granted by the source; a service worker or WebAssembly converter cannot grant it. Sources: [recorded probes](browser-asset-probe-results.json), [Fetch CORS protocol](https://fetch.spec.whatwg.org/#http-cors-protocol).

Even with a readable source, a conversion port is substantial. Current scripts extract Unity object data and textures through UnityPy, unpack password-protected media archives, extract Spine skeletons and atlas dependencies, concatenate split voice files, and convert some movies with FFmpeg. Later story tables use SQLCipher and FlatBuffer decoding with committed schemas for the pinned database. That database is about 209 MiB before processing in the sampled catalog, so mobile storage and memory costs also need measurement. Sources: [asset extraction](../scripts/ba-assets.py), [database extraction](../scripts/ba-event-source.py), [main-story schemas](../scripts/ba-main-source.py), [database size probe](browser-asset-probe-results.json), [upstream downloader requirements](https://github.com/ZM-Kimu/Blue-Archive-Asset-Downloader).

This verdict is limited to the sampled JP version and paths. It does not establish the headers of every BA region or every external mirror. Under the current source selection, do not promise automatic browser downloads. A CORS-enabled third-party source would need validation; an extension or native application can use a different request model, but adds a product requirement beyond an ordinary PWA. A developer-operated proxy conflicts with the requested release architecture.

## GFL1

The implemented source is an installed Steam English client. The extractor reads `GirlsFrontLine_Data/StreamingAssets/Res/Pc`, discovers a Steam installation through local configuration, and rejects a missing resource directory. It loads `assettextavg.ab` and `assettextes.ab` through UnityPy for original scripts and metadata. It resolves backgrounds, portraits and dependencies from other local Unity bundles. Catalog relationships and ordering use installed STC tables. Sources: [extractor](../scripts/gfl1-extract.py), [catalog extractor](../scripts/gfl1-catalog.py), [pipeline notes](gfl1-pipeline.md).

Audio follows the installed AudioTemplate and native CRI banks. Extraction calls native vgmstream and FFmpeg, producing browser-playable Ogg. The importer then compiles extracted scripts into chapter JSON and publishes local `/private/gfl1/...` URLs. Sources: [audio extraction](../scripts/gfl1_audio.py), [chapter importer](../scripts/import-gfl1.mjs).

The current text archive references public community repositories as corroboration for particular missing scripts and audio aliases. Those references do not establish a complete, supported downloader for all required art and sound. The checked extraction code contains no general publisher manifest or asset-CDN downloader. Sources: [pipeline source audits](gfl1-pipeline.md), [alias evidence](../scripts/gfl1-audio-aliases.json), [extractor](../scripts/gfl1-extract.py).

There is a concrete alternative to the installed client: [gf-resource-downloader](https://github.com/gf-data-tools/gf-resource-downloader) supports regional manifests and constructs resource URLs from their asset host and resource names. The [gfStory-en build workflow](https://github.com/shiropantsu/gfStory-en/blob/main/.github/workflows/build.yml) consumes the US manifest, runs this downloader and then native unpacking tools. This establishes an existing acquisition implementation to investigate. The [US host configuration](https://github.com/gf-data-tools/gf-data-us/blob/main/hosts.json5) includes HTTP URLs; HTTPS support and mixed-content behavior need checking before browser adoption.

Browser feasibility remains unproven for automatic downloads on a new machine. Next, test that downloader's manifest and asset endpoints from the deployed browser origin, confirm required coverage for the selected region, and compare their format with Onlystory's Steam-derived extraction. No GFL asset endpoint was probed in this audit. A local-file import path has a known source format, but still needs user file selection and browser replacements for UnityPy, texture extraction and CRI audio conversion. Existing Python extraction is not a browser implementation.

## GFL2

The implemented source is an installed Windows CN game's local cache plus recovered development inputs in the sibling `onlystory-gfl2` project. Chapter text joins exported original `.book.json` commands with installed localization/content tables. Some source-book extraction and model recovery depend on the sibling project's Addressables/GFF resolver and recovered settings. Sources: [text importer](../scripts/gfl2-event.mjs), [event extraction](../scripts/gfl2-extract-event.py), [text recovery notes](gfl2-full-text.md).

Character extraction reads physical cache segments, reverses their recorded header obfuscation, loads Unity objects with UnityPy, and reconstructs original MOC3 models, model metadata, expressions, motions and texture atlases from prefab references. The known dependency graph is useful for a browser port, but the current code operates on installed files. Sources: [character extractor](../scripts/gfl2-characters.py), [character findings](gfl2-character-findings.md).

Background and sound recovery also reads the local cache. CRI HCA audio uses pinned vgmstream with the recovered game key and AWB subkey, followed by FFmpeg conversion. Retained verification found incorrect audio from the native FFmpeg HCA decoder, so a browser conversion must validate PCM against the working decoder rather than merely accept a successful decode. Video export preserves H.264 picture data and decodes selected ADX voice tracks before AAC/MP4 output. Sources: [media extractor](../scripts/gfl2-media.py), [media findings](gfl2-media-findings.md), [video extractor](../scripts/gfl2-videos.py).

There is an existing network acquisition script for official promotional cover images. It queries a publisher website API and retrieves the selected image URLs. This establishes a source for covers only, not for original story books, Live2D models or CRI banks. It uses a native `curl.exe` subprocess, which does not establish browser CORS access. Source: [cover downloader](../scripts/gfl2-covers.py).

An external model provider also exists: [srpg-kr/l2d-assets](https://github.com/srpg-kr/l2d-assets) publishes extracted Live2D resources through GitHub Pages. Its [viewer configuration](https://github.com/srpg-kr/srpg-kr.github.io/blob/main/src/live2d/lappdefine.ts) points to `https://srpg-kr.github.io/l2d-assets/Resources/` and lists GFL2 character models. This is a candidate for models, textures and motions, not evidence of a complete story source. Browser access, model coverage and compatibility with Onlystory were not tested.

Automatic full-content browser acquisition remains unproven. The next source investigation must validate this model provider and establish sources for original scripts, backgrounds and sound. If using the game's packages instead, document its actual patch/catalog delivery flow, test public versus authenticated requests, and map packages to the existing cache resolver. Even with successful downloading, the sibling parser dependencies and native conversions must be packaged or replaced for the browser. A local game import can reuse the known format, but does not satisfy new-machine automatic downloads by itself.

## Browser constraints shared by the games

- A readable cross-origin `fetch` needs the upstream server's CORS permission. A successful Node/Python/curl request proves connectivity, not browser access. Installing the PWA does not change this request policy. `no-cors` supplies an opaque response whose body is unavailable to the app, so it cannot feed bundle parsing or hash verification. A service worker is not a CORS bypass. Source: [WHATWG Fetch standard, CORS protocol and filtered responses](https://fetch.spec.whatwg.org/).
- Native command-line programs and filesystem paths in these importers need browser implementations. A practical prototype must prove package decompression, Unity object and texture decoding, model dependency reconstruction, and CRI decoding on representative content. Existing browser playback proves that the exported formats render; it does not prove that raw game formats can be imported efficiently on a phone. Sources: the GFL extractors linked above.
- Local game files require an explicit user file/directory selection. `showDirectoryPicker` requires user activation and is not supported across all major browsers, so it cannot be the only universal import mechanism. Source: [MDN directory picker API and browser compatibility](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker).
- Offline files live within browser storage limits. Downloads need quota estimates, recoverable partial states, deduplication, and a persistence request. Persistence is browser-controlled and does not protect data from deliberate user removal. Sources: [WHATWG Storage standard](https://storage.spec.whatwg.org/), [MDN storage quotas and eviction](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

## What to prove before promising automatic downloads

For each game and supported region, reproduce a fresh-browser download of one original chapter with its actual text, models, textures and audio. Record the source/version manifest, redirects and access requirements, readable bytes from the deployed origin, conversion output hashes, mobile time/memory use, and an offline restart. Test a video and a shared dependency as separate cases. Until that exists, label the provider experimental rather than advertising a complete downloadable library.

Keep downloaded raw bundles and converted outputs in app-managed storage and make the app resolve the dependencies. This provides the requested practical friction for casual extraction. A determined person can still reproduce public download requests and reuse client-side decoding code; encryption with a key shipped to the same browser cannot enforce app-exclusive access. This is an architectural inference from the app needing both readable source bytes and conversion logic locally.
